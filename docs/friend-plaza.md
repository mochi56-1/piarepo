# 承認済みの友達の広場

## 有効化する手順

1. 既存のアカウント・友達用SQLが設定済みであることを確認する。
2. SupabaseのSQL Editor → New queryに [`202611040001_friend_plaza.sql`](../supabase/migrations/202611040001_friend_plaza.sql) の全文を貼り、Run。既存の非公開記録やコインを削除しない。既存のお試し公開noteを自動公開するバックフィルも行わない。
3. この版のVercelデプロイがReadyになったらアプリを再読み込みする。SQL未設定でも記録機能は継続し、共有の選択肢は無効・広場は設定待ちになる。
4. マイページ → 友達・QRコードから友達を承認する。
5. noteの3番目の画面で「友達に見せる」を選んで記録する。過去のnoteは編集するか、メニューの「友達に見せる」を明示して共有する。自分だけを初期値にする。
6. 相手のアカウントの「広場」→ 更新で表示されること、スタンプ・追加スタンプ・コメント・コメント削除を実機で確認する。
7. 自分だけへの変更、友達解除後に相手から最新の閲覧・書き込みができなくなることも確認する。既に表示・保存された情報を相手の端末から消すことはできない。

共有可否の能力チェックRPCを使用するため、コードを先にデプロイしても未設定時に共有が有効になることはない。SQL設定後はアプリ全体を再読み込みする必要がある。公開URLや環境変数・管理者キーの追加は不要。

## データの分離

- 非公開の全記録：従来の`account_records`。他人からは読み書き不可。
- `friend_notes`：明示した`shareToFriends: true`のnoteだけ。保存時のDBトリガーで、タイトル・本文・日付・時刻・気分・写真だけを取り出す。任意のJSONや履歴・振り返り・タスク・予定をそのまま公開しない。
- `friend_stamps`：note所有者＋note ID＋反応した利用者＋スタンプ種類を主キーにする。1人が同じ種類を何度も加算できない。
- `friend_comments`：本文・作成日時・作成者。リクエストUUIDで、応答を受け取れず再試行した場合の重複送信を防ぐ。自分のコメント、または自分のnoteへのコメントは削除できる。
- 表示名は友達プロフィールのものを利用する。メールや招待トークンは広場に返さない。
- 全テーブルRLS有効。本人・承認済みの友達のみ閲覧でき、申請中・第三者・匿名には不可。テーブルへの直接書き込みは不可で、RPCが認証IDと現在の権限を検証する。
- 書き込み時は対象noteと友達関係の行をロックし、解除や非公開化と反応書き込みの競合を制御する。
- 自分だけに戻すと共有用のコピーと、そのスタンプ・コメントを削除する。再公開しても元の反応は戻らないため画面に明記する。
- バックアップ取り込みで新たに追加するnoteは自分だけに戻す。同じIDのクラウド記録を優先する全記録取り込みでは、既存の公開状態を勝手に変更しない。note専用バックアップの上書き復元は従来の確認を行い、取り込むnoteを非公開にする。

## 表示と制限

- 1ページ10件。自分が共有したnoteと、承認済みの友達の共有noteを更新順で表示する。
- コメントは各noteの最新50件を表示し、全件数を併記する。スタンプは既存5種と「＋」の8種を利用する。
- 更新ボタン・フォーカス復帰・自分の記録保存完了・友達画面を閉じた際に再取得する。常時リアルタイム配信ではない。
- ゲストは実際の友達広場には接続しない。ログイン前の広場は従来のお試し表示。
- 共有側の反応を、自分のprivate JSONに書き戻して件数を操作する方式にはしない。自分のnoteの反応は広場で確認できる。
- 共有用にも画像コピーを持つ。現在の画像込み文書方式は小規模向けで、画像用private Storageと個別記録テーブルへの移行は別途必要。
- 有料プラン・動画広告・着せ替え購入はこの更新に含めない。

## 検証

PostgreSQL互換のPGliteで実際のSQLを実行し、明示したnoteのみの公開、許可フィールドのみの投影、private JSONへのアクセス拒否、申請中・第三者の拒否、スタンプ・コメントの二重送信防止、直接書き込み拒否、編集と非公開化、友達解除、ページ分割、画像URLの制限、匿名RPC拒否、再実行でデータを残すことを確認。

Chromiumの模擬Supabaseで、友達noteの表示、基本／追加スタンプ、通信失敗後のコメント再送、コメント削除、明示した公開設定、保存後の広場更新、幅320〜1440pxの表示、SQL未設定時の共有無効化を確認。本番SupabaseへのSQL実行やVercelのReadyは、ツール接続がないためこちらから検証できない。
