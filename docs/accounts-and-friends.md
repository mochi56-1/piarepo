# アカウント保存とQR友達申請

## 公開前に行うこと

1. 現行のnoteバックアップを保存し、必要ならタスク・予定も控える。今回の更新はブラウザ内の元データを削除しない。
2. SupabaseのSQL Editorで [`202610290001_accounts_and_friends.sql`](../supabase/migrations/202610290001_accounts_and_friends.sql) を全文実行する。既存のコイン用SQL・設定は残す。このSQLは再実行可能で、既存の記録・コイン・友達を削除しない。
3. SQLが成功してからコードをVercelへデプロイする。環境変数は今までの公開URL・公開キーを継続利用し、管理者キーは不要。
4. 公開サイトでログインして自分の記録だけが表示されることを確認。既存データの件数とログイン中のアカウントを確認して「このアカウントに取り込む」を押す。自分のnoteのみを対象にし、デモの他人のnoteやデモ友達は取り込まない。元のブラウザデータは残す。確認なくデータを別のアカウントへ取り込まない。
5. 保存後に別端末の同じアカウントで開く。別アカウントでは空の記録から始まること、ログアウト後に記録が表示されないことを確認する。
6. マイページ → 友達・QRコードで表示名を設定。別アカウントのスマホカメラからQRを開き、表示名を確認して申請する。受信者が同じ画面で一覧更新 → 承認。逆方向の申請も自動承認しない。
7. 更新したプライバシーポリシーを確認する。クラウド移行後は日記・画像もSupabaseに送信することを利用者に案内する。

## 画面の動作

- 設定済み本番環境では未ログイン時に記録を出さない。認証やDB設定の失敗をローカル保存に切り替えない。
- 以前のデータは確認後にのみ取り込む。同じ数値IDの記録はクラウド側を優先し、データを勝手に上書き・削除しない。必要なら元のバックアップを残して比較する。
- 保存中は追加編集を止め、通信失敗時は未保存内容をメモリに保持する。再試行または未保存の全記録をダウンロードできる。ページを閉じると未保存の内容は失われるため、画面の警告に従う。
- 別端末の変更は画面を開き直すか「最新を読み込む」で取得する。リアルタイム同期・自動マージはない。
- 同時編集はrevisionによる楽観ロックで検出し、古い端末の内容で上書きしない。競合時は未保存内容をダウンロードし、最新版を読み込み、必要な内容を確認して反映する。
- 「全記録バックアップ」はnote・写真・履歴・振り返り・タスク・予定。取り込みは既存ID優先のマージで、削除や同じIDの上書きはしない。コイン・友達情報は含まない。従来のnote専用バックアップも利用可能。
- デモのスタンプ・コメントは独自のユーザー間共有機能ではない。クラウド版も広場は自分だけの表示。友達関係ができてもnoteを公開しない。実際の共有は別の公開データ設計が必要。
- 通知設定など一部端末設定と旧記録はローカルに残る。共用端末では取り込み・バックアップ後、元のサイトデータの扱いを確認する。

## 保存とアクセス制御

- `account_records`：本人のnote・画像・タスク・予定を1つのJSON文書として保存。本人にだけSELECT可能。書き込みは`save_account_records(payload, expected_revision)`のみ。ユーザーIDをクライアント引数に取らず`auth.uid()`から決定する。
- `friend_profiles`：表示名、ランダムな招待UUID。本人のみ直接参照可。招待リンクを知るログイン利用者だけがRPCで相手の表示名を確認できる。メールアドレスは扱わない。
- `friend_connections`：申請者・受信者・状態・日時。同じ2人の組み合わせは方向によらず1件。本人の関係のみ参照でき、承認は受信者に限る。解除・取り消しは当事者のみ。
- 招待リンクは失効時刻のない再利用可能なリンク。QR内に認証トークン・メール・日記本文は含まれない。リンク更新で古いものを無効化できる。QRは`qrcode`で端末内生成し、外部QRサービスへ送信しない。
- 全テーブルRLS有効、直接のINSERT/UPDATE/DELETEは認証済み利用者にも不許可。公開関数は空search_pathを指定し、匿名実行を許可しない。
- SupabaseのテーブルやSQLにユーザーデータが保存されるため、運営者による管理アクセスまで暗号的に防ぐE2E暗号化ではない。

## 現段階の容量・構成の制限

今回の小規模版は画像をData URLとしてJSONに含め、アカウントの文書全体を保存する。画像は既存の1枚2MB上限、文書全体はDBで30MB上限。変更ごとに文書を送るため、大量の画像・記録には向かない。利用規模が増える前に、private Storageバケットと個別のnote・task・eventテーブルへ移行する。バケットは今回使用しない。容量上限・通信失敗時も保存成功とは表示せず未保存画面へ移る。

アカウント削除はアプリ内未実装。本人からの問い合わせに運営者が対応する。Supabase Authユーザー削除で今回のテーブルとコイン履歴は外部キーのCASCADEにより削除される。ブラウザ側の旧データ・ダウンロード済みバックアップは別途本人が削除する。
